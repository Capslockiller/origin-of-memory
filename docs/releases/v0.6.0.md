# Release notes — 0.6.0

An audit week. Astra read the mechanism against its own claims, and most of
this release is the repair list: the memory stops talking over you, stops
counting the same money twice, stops calling a guess a measurement, and stops
depending on a session ending politely.

## Astra week-1: the session start goes on a diet

The UserPromptSubmit hook was injecting concept notes into almost everything.
Two doors were open at once — the live registration calls `retrieve.py hook`
directly, while the `BEYIN_INVOKED_BY` recursion guard lived only in the
retired PowerShell wrapper — so every child the compiler, flush or the
benchmark harness spawned got the user's personal notes pushed into it. The
hook now exits silently on an internal call, and applies a relevance gate
before it injects: an intent skip for pure code and tool commands, and a
requirement that at least two distinct content words of the prompt appear in a
candidate note's own title, aliases or tags — the body is excluded, because
"mentions the word" is not "is about it". Measured against the live 527-note
index on the same 30 probe prompts: before, 30/30 injected; after, 13/15
memory-worthy inject and 0/15 non-memory inject. Session dedup was also keyed
on the note name alone, so a note shown once was suppressed for the rest of the
session no matter what was asked next; the key is now query-signature plus note.

## Astra week-1: the numbers stop lying

`harcama_defteri.py` summed every copy of every assistant message. Claude Code
re-emits the same response on streaming updates, retries and compaction
rewrites, and each copy carries its own `usage` block. Measured over the real
`~/.claude/projects` (1,740 files): 50,596 raw `usage` rows collapse to 22,036
distinct responses. Every recorded figure had been inflated roughly 2–3× —
cache-read tokens for 1–6 September fall from 1,477M to 716M, output tokens
from 12.9M to 4.7M. Responses are now keyed by `message.id`, and the daily
breakdown is built from each usage record's *own* timestamp instead of the
session's last one, so a session crossing midnight no longer moves its whole
spend onto the wrong day.

`kota.py` had the mirror-image problem. Its OAuth cache had been frozen for 36
hours, yet every read appended a fresh-timestamped sample of the identical
percentages: Δused came out 0, the burn ratio came out `R 0,0`, and the
governing band came out `serbest` while the status line was already printing
`[oauth 2050dk bayat]`. Windows now carry the timestamp of the *server
observation* behind their percentage; past the staleness threshold the band is
`bilinmiyor`, never `serbest`. The follow-up mattered as much: a Codex reading
is not stale merely because Codex has been idle. Codex percentages come from an
event log, not a polled cache, so silence means "no new events" and the last
observation stands until its `resets_at`. `KURAL_YAS` and `KURAL_RESET` now
name those two animals separately.

## Astra week-1: flush gets a delivery contract

Flush had no way to prove it had run. A missing transcript returned 0 with no
state, no health entry and no trace at all — the live vault's state directory
held 127 per-session locks against 14 result files. Every attempt now appends
one line to `.state/flush-teslimat.jsonl` (counts only, never transcript text),
and every failure mode raises a health warning carrying its reason code. The
60-second duplicate guard is replaced by a per-session turn cursor that
advances only after the daily append lands, so a crash costs a repeat, never a
gap — the old guard had let one unchanged transcript be summarised twice, 33
minutes apart, at 9,862 identical model-input characters both times.
`format_turns` now reports the turns that survived *both* caps rather than the
pre-character-cap figure; it had said 30 while sending 23.

## The debts

Five mechanism debts came out of the same audit. `bakim.py` rotated
`enjeksiyon.jsonl` under `scripts/.state` while the live hook writes it to
`hooks/.state`, so rotation had never run in production. `flush-launch.ps1` and
`session-start.ps1` now write one line to `hook-girdi.jsonl` before they read
stdin, so "the hook never fired" can finally be told apart from "the hook fired
but Python never started" — the question session 54's lost 19-hour transcript
could not answer. `memory-retrieve.ps1` is now a thin shim over `retrieve.py
hook` instead of a second gateless door; it is kept, not deleted, because that
registration is the owner's call. `secret_guard` gained a `contextual-code`
rule for credentials that only their label gives away: a one-time login code
handed to a pilot user had passed both `secret_guard.scan` and
`pii_guard.redact` with no hits at all. And the retrieval, flush, kota, durum
and ledger docs were realigned with the code they describe.

## Purpose tags and three budgets

Every model call now says why it ran. `record_call` takes a `purpose` from a
closed vocabulary (`capture`, `extract`, `concept`, `retrieve`, `ingest`,
`benchmark`, `hand-memory`, `work`), a repo-wide grep test fails if a new call
site omits it, and `durum.py` splits the window three ways: `bakım`,
`geliştirme`, `iş`. The point is to make the cost of *keeping* the memory
separable from the cost of the work the memory is for. In the same pass
`usage_source` lost its `estimate` value: it is `session-log` when the provider
reported real usage and `unknown` otherwise, and on `unknown` the four real
token fields are forced to `null` rather than trusted — a chars÷4 figure can no
longer reach `input_tokens`. Components with no provider figures used to vanish
from the real-usage table, which reads as "it cost nothing" when it means
"nobody counted"; they are now listed with an `unknown: N calls` column.

## Flush stops depending on a polite goodbye

`SessionEnd` is a courtesy, not a guarantee — when the app or the machine is
killed the hook is never delivered, and session 54 lost 19 hours that way.
`flush.py --tara` sweeps `~/.claude/projects` every 8 hours through a scheduled
task and runs the same per-session path as the hook. It does nothing when
nothing changed: an mtime/size stamp per transcript plus the existing turn
cursor mean a transcript that grew by tool results alone calls no model at all.
A session held by a live hook flush is taken non-blocking and left alone.
Measured with `--dry-run` against the live archive before shipping: 1,749
transcripts, 17 changed in the last 8 h, 16 that would be summarised, 0 errors.
The nightly compile gate relaxed in the same decision to "≥18:00 **or** ≥20 h
since the last recorded success" — the evening hour alone had meant a machine
only awake during the day never compiled at all.

## Suite

1,054 passed and 1 skipped without `test_gui_wizard.py`, plus 11 passed in
`test_gui_wizard.py` under PowerShell — 1,065 tests. The v0.5.0 notes recorded
837 passed, 1 skipped.

## Not verified

- The live `calls.jsonl` still shows **zero provider-measured calls**. The real
  usage plumbing lands in this release, but nothing in the live vault has yet
  been recorded with `usage_source: session-log`, so the honest-accounting path
  is proven by tests, not by production data.
- The Terra and Luna tiers are **unmeasured**. Nothing in this release ran
  against them.
- `gemini_ayikla` is adopted into the repo at `tools/gemini_ayikla.py`, but an
  installed vault carries a **personalised derivative** under
  `.claude/scripts/` whose keyword table diverges on purpose. The repo copy is
  the one that is tested; the vault copy is not.
- The auditor's figures throughout these notes are **re-derived from
  transcripts, not billing**. The 2–3× inflation, the 716M cache-read tokens
  and the injection counts are measurements against local files and a local
  index; no provider invoice was consulted, and no claim here is reconciled
  against one.
- The scheduled `--tara` sweep was exercised with `--dry-run` against the live
  archive and by unit tests, but a full 8-hour production cycle of the
  registered `OdenaOS-Flush` task has not yet run to completion and been
  reviewed.
- No `OriginOfMemory-Setup-0.6.0.exe` is built. The `.iss` script reports
  0.6.0, so an executable can be built from this exact tag with Inno Setup 6
  and `installer/build.ps1`; the source zip's `Setup.cmd` does the same job.
