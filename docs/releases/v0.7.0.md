# Release notes — 0.7.0

Phase 1 of the core audit. 0.6.0 proved the mechanism was not doing what it
claimed; this release is the first pass at making it do it. Four lanes shipped
together — the session start stops burying what is current, a correction is
something the compiler is accountable for, flush has a delivery contract and an
hourly reconciliation, and the human-written Companion layer is finally
searchable — and three follow-ups (I2, I3, I4) closed what the acceptance run
found. In the middle of it the summariser moved to Claude Haiku, which promptly
exposed a loop where the sweep was summarising its own transcripts. That is
fixed here too.

## Current facts stop being crowded out at session start (lane D)

`e9a6d38`. The SessionStart injection had no ordering discipline: when the
budget ran short, whatever came last was cut, which in practice meant the daily
tail and the root map — the two things carrying what is true *today*. Journal
(and, once it exists, a Threads body) now yields before those two floors, and
the volatile time/quota suffix comes last so it is dropped first. Same-second,
same-cwd duplicate starts — a helper process opening beside the session that
spawned it — get a minimal notice instead of a second full pack.
`enjeksiyon.jsonl` gained `session_id`, `cwd`, `cift` and the names of the
trimmed sections, so a thin injection can be read back rather than guessed at.

## A correction becomes an input the compiler answers for (lane B)

`0ad817d`. Telling the memory it is wrong used to mean editing a note and
hoping the next compile did not undo it. `scripts/duzelt.py` now owns a
plain-text store at `🔮 850-Companion/Duzeltmeler.md`: one block per correction,
a single-line machine comment carrying slug, state, timestamp and source, then
an `iddia:` line (the wrong sentence) and a `dogru:` line (the right one). The
grammar is line-oriented on purpose, because retrieval reads the same file at
query time without the compiler in the loop.

`compile.py` reads pending corrections as a separate high-authority block placed
before the daily, screened field by field with the same directive-shaped
detector the untrusted blocks get. What matters is what happens after promotion:
`duzeltme_kapanisi()` verifies. An entry closes only when the claim has actually
left the live note **and** the correction has landed, judged by normalised
containment plus key tokens — dates, amounts, case codes — a claim counting as
present when all its key tokens share one sentence. "The file changed" is no
longer proof. An unapplied entry stays `bekliyor`, keeps its health warning, and
appears in `durum.py`'s new `bekleyen duzeltme` row with the age of the oldest
one. A missing or unreadable ledger can never fail a compile: the prompt is then
byte-identical to the previous version.

## Flush proves delivery, and reconciliation becomes the signal (lane A)

`90ede72`. Chunks now commit exact, contiguous ranges instead of discarding a
capped prefix: oldest-first, deterministic daily range markers, survival of an
append-before-state crash without a duplicate block, a bounded drain (three
chunks / 180 seconds by default), and a failed chunk parked after three attempts
without advancing `kapsanan`. Above that sits the hourly sweep and
`.state/mutabakat.json`: a 20-minute quiet window with a four-hour oldest-turn
override, then a written reconciliation manifest that `durum.py` reports —
uncovered sessions and the age of the oldest uncaptured source. Hook launch
records now carry the child PID and start status, Python writes PID-addressed
capped stderr logs, and reconciliation warns when there is ingress with no
matching delivery evidence. The summary validator was loosened in the same lane
after it threw away 6 of 20 Haiku summaries that were fine on retry; a rejection
now writes the raw output to `.state/red/` instead of being a verdict with no
evidence.

## The hand layer is searchable, and its authority is bounded (lane C, I2, I3)

`b739813` indexed `Last-Session.md`, `Threads.md` and `Journal.md` as
heading-split, provenance-bearing passages sharing the FTS5 index with concepts
(schema 3), and routed `Duzeltmeler.md` through `duzelt.ayristir()` so the block
grammar has exactly one owner.

Then two corrections. `d21bddc` (I2): the hook's relevance gate counts overlap
against a hit's title, aliases and tags, which works for a concept note written
on purpose at compile time and fails for a Companion passage whose heading was
typed in the moment. Measured live, a question about a Speaking date and fee
ranked the `Threads.md` passage first through the CLI while the hook injected
only the stale concept note, because the passage's metadata overlap was the
single word `speaking`. Hand passages now also get the first 400 characters of
their own body folded into the gate pool, through the same token rules; concept
notes are untouched, so lane C's anti-junk behaviour holds.

`fa26d7e` (I3): lane C let any Companion passage scoring 60% of the best concept
jump every concept note, and the 125-question concept gold set fell from a
102@3 / 110@5 baseline to 94@3 / 103@5. Authority is now a margin, not a
discount — a hand passage must *outscore* the best concept by a factor whose
default rose from `0.6` to `1.35`, must come from a file on an explicit list
(`Last-Session.md,Threads.md`; `Journal.md` stays searchable but is narrative
prose and never ranks hand-first), and at most two of them may sit ahead of the
concepts. The gold set returns to 103@3 / 110@5, which is exactly the ceiling
the same corpus reaches with authority switched off entirely, and mean injected
context per event drops from 2,089 to 1,412 characters.

## What the acceptance run measured

From the owner's `faz1-kabul-2026-09-08.md`. Current-fact ("episodic") questions
went from **1/10 to 8/10 through the hook**, and answer **10/10 at the query
level** — the gap between the two numbers is the hook's relevance gate, and it
is deliberate. The fabricated-note case is the one to read carefully: the wrong
answer is still reachable on both paths, but a correction block now appears
alongside it instead of the note being silently trusted. The concept gold set
stands at 103/110 after I3, against a 110@5 baseline that is the same ceiling
the corpus reaches with authority off. Injected volume per event stays at or
under 4,500 characters. One deviation was accepted rather than fixed: the
"hafıza kaybı" junk case produced a diagnosis note instead of the expected
behaviour, and was recorded as such.

## Who writes the summaries

`ecb732a`. The 2026-08-30 decision to summarise sessions on a local model is
reversed. On the same sessions the fabrication/junk rate came out **14.5% for
the local 8B, 8.8% for the local 30B and 5.9% for Haiku**, and the flagged case
that triggered the review failed 3/3 locally. Haiku is the primary summariser;
the local 8B stays in the launcher as a manual fallback for offline or
quota-closed operation. Automatic fallback is not in this release.

## The summariser summarising itself

`24eab40` (I4) — the cost of the previous section. With a Claude backend, every
flush, ingest and `kaydet` call leaves a `claude -p` transcript of its own under
`~/.claude/projects`, written from the temporary working directory those calls
run in. The sweep read them as human sessions. The loop was caught at 19:30 on
2026-09-08 after it had produced **21 junk blocks**, which have been archived
out of the daily log; the `beyin-*` temp directory markers are now excluded the
same way `stage-compile` and subagent transcripts are, with a test pinning both
directions.

## After deploy

The live numbers once Phase 1 was running: **84 ghost anchors retired**; **2
correction records** in `Duzeltmeler.md`; the index at **schema 3 with 534
concepts and 129 hand passages**; the sweep moved from 8-hourly to **hourly**;
the reconciliation ledger reporting **86 sessions with 73 not covered**, 15 of
them from 29 August onward. That last number is the honest one and it is not
good: backfill is a later phase, and until it runs the ledger measures the gap
rather than recording coverage.

## Suite

1,215 passed and 1 skipped in 127.84 s — `python -m pytest` from the repository
root (`testpaths = scripts/tests`) on Windows 11 with CPython 3.12.10 and pytest
9.1.1, the same command CI runs on `windows-latest` across 3.12 and 3.13. The
owner's session record says 1,213; the two extra are the tests added with I4.
The v0.6.0 notes recorded 1,054 passed and 1 skipped, plus 11 GUI tests run
separately.

## Not verified

- **No `OriginOfMemory-Setup-0.7.0.exe` is built.** The `.iss` script reports
  0.7.0, so an executable can be built from this exact tag with Inno Setup 6 and
  `installer/build.ps1`; the source zip's `Setup.cmd` does the same job. Same
  position as 0.6.0.
- **Phase 2 has not started.** A6-B (session start under 10k), A5-2 (passages)
  and A-R (the ledger) are open, as are defects #34, #36 and #37. Nothing in
  this release touches them.
- **The 73 uncovered sessions are not backfilled**, including the 15 from 29
  August onward. Reconciliation reports them; nothing yet repairs them.
- **The two correction records are still open.** They wait on the 02:00 compile
  to run `duzeltme_kapanisi()` and close them, so the verification half of lane
  B is proven by tests and not yet by a production cycle.
- **The acceptance figures are the owner's measurements**, taken against the
  live vault on 2026-09-08 and recorded in `faz1-kabul-2026-09-08.md`. They are
  not reproduced by this repository's test suite, and no number in these notes
  comes from billing data.
